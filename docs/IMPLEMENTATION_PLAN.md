## 2. 执行规则

### 大步实现、小步验证

- 大步按用户可用的端到端能力闭环划分，不按文件、类或技术层交付。
- 大步内部先理解与取证、细化计划，再实现、验证及修复。必要依赖只做当前闭环需要的部分，避免提前铺大框架。
- 进入某大步获授权后，自主完成范围内实现、构建、验证、常规修复与收尾；不把每次编译或测试变成人工审批。
- 每个大步实现完成后交付结果与证据，状态为“待用户验收”；用户明确确认后才进入下一大步。自测通过不能自行改为用户已验收。
- 重大设计变化、范围扩大、破坏性处理或不在授权内的环境变更先报告具体事实、影响、备选和推荐，等待决定。
- 能从工程或环境查到的事实先查，不把资料查询交给用户。资料不足时明确列出缺项；不以愿望清单替代可执行任务。

### 代码、注释与临时实现

- 按现有有效风格和明确职责实现真实能力；禁止 Mock、空实现、固定成功响应或硬编码演示路径冒充产品功能。
- 确定性测试输入、故障注入可作为验证手段，但必须明确边界，并走真实接口与实现，不冒充硬件或生产能力。
- 函数承担独立清楚职责，不增加只转发调用或一两行赋值的无意义封装。不为假设需求预埋抽象、状态、扩展点或长期兼容层。
- 统一覆盖模块、接口、函数、复杂逻辑及边界处理的注释，说明职责、关键约束和原因，避免逐行复述。
- 调试、过渡和兼容代码必须用起止注释包围，写明原因、范围及移除条件；不能借“临时”绕过正式完成条件。
- 不预建空源码目录或空框架。旧算法和实现逐项评估复用，旧全局 Controller、固定主窗口接线和中心命令表不能整体迁回。
- 对第三方依赖核对版本、许可、目标平台和实际行为；不凭 README 宣称集成完成。保留现有 LGPL-3.0 方向，重大选型问题报告用户。

### 文件与 Git

- 文件操作以当轮明确授权为准；未授权不任意创建、修改、删除或移动文件。源码实施指令必须明确本轮范围及必要文档更新。
- 当前初始化保留原决策记录，新增架构、计划、映射、进度文档；不创建 AGENTS.md，不提前写正式 README。
- 原决策记录作为历史依据，不将施工者的新建议写成用户已确认决定。实际新增设计决定说明依据及影响，重大变化先确认。
- 不直接执行或移植旧归档的清理、安装、联网升级或打包脚本。外部程序默认后台非交互，明确程序与参数。
- 没有当轮明确 Git 指令，不建仓库、不提交、不推送、不建 PR；当前分支整理授权仅用于本轮初始化。
- 获明确推送授权时，按功能和行为边界原子提交，结合调用关系、历史和改动顺序整理；推送前查远端、分支、范围，推送后查工作区、tracking 和远端 HEAD。
- 本轮 `archive/pre-0.5.0` 保留原云端 main 的提交；新 main 通过正常后续提交形成，不强推、不重写历史，不改 gh-pages、标签或已有发布。

## 3. 验证与交接规则

验证从成本低的检查推进到真实集成。代码检查、构建、局部行为、公开入口调用、跨进程或 GUI 等按本步影响选择，不以测试数量替代实际行为。已有检查通过后，不无理由反复跑全套。

证据在实际执行后写入 `verification/<大步编号>/`，包含提交或工作树状态、环境与依赖版本、输入和规模、操作/命令、预期与实际结果、退出状态、必要日志和产物位置。保存可重跑的步骤，不能只截一张“成功”图片。不得记录密码、令牌或私人数据。

接口返回受理或任务 ID 后继续跟踪到终态，检查结果、文件和资源释放。验证取消、错误与失败收尾，不把“未崩溃”当成正确。

Windows x64 是正式验收目标。WSL/Linux 结果仅证明对应环境；没有硬件时可验证软件或回环，但物理设备行为仍标未验证。新架构不能继承旧版测试成绩。

每个大步结束同步：
- PROGRESS：当前状态、已完成内容、证据、阻塞和下一步。
- FEATURE_MAP：本步涉及能力的实现位置、场景与验证状态。
- 本计划：确有必要的任务边界或进入条件调整，区分用户决定与实施细节。
- ARCHITECTURE：获确认的稳定设计变化，不能写入阶段进度。

最终报告给出“能做什么、怎样验证、还缺什么、是否达到完成条件、下一步是什么”。不能只列改动文件。

## 5. M1：真实运行链路

**结果**：使用正式节点模型装配离线信号处理工程，通过公开 CLI 操作 C++ 信号源与 Python 独立进程滤波，得到可核对的文件输出。

实现思路：入口携带必要读取代码，按真实工程与节点声明绑定公开接口；官方运行实现复用 ROS 通信与执行。类型定义及语言支持在构建阶段生成。Python 工作者真实执行计算，不用 shell 管道或固定脚本直连绕过节点接入。

最小正式 `.crnd`/`.crnp` 内容、接入约定和类型格式在本步定义。允许开发使用同一模型的展开目录，但交付需验证最小正式包读入与工程保存重开；M2 再补齐复杂引用、完整收纳及加解密，不另造临时 schema。

步内验证：
1. 核实 Windows 工具链、ROS 和两种语言支持的当前环境；定义当前必要接入、生成与启动规则，记录版本和原因。
2. 从构建产物实际装入节点，公开发现接口，不通过修改入口注册新的业务节点。
3. 消息：有限已知序列经过滤波写文件，逐项核对数值、数量、顺序与来源；正常场景不允许实时跳批默认吞掉验证数据。
4. 服务：读取并修改参数，检查配置值、生效值及非法参数拒绝后原值保留。
5. 动作：真实有限批处理，检查进度、结果、失败及处理中取消；检查取消后的文件实际内容与进程退出。
6. 缺依赖、类型不匹配、启动失败及工作进程退出能定位具体实例；按示例明确流程收尾，不把其策略升格为所有节点强制规则。
7. 保存重开后重复运行；独立实例状态不串扰，结束后无遗留工作进程和文件占用。

完成条件：在 Windows x64 可重跑上述场景，公开 CLI 跟踪终态和真实输出；材料足以独立构建、运行和核对。提交 M1 证据后等待用户验收，不进入 M2。

## 6. M2：文件与完整交付闭环

**结果**：工程能跨目录或干净环境保存、重开、运行，引用和收纳可检查，并可从实际收纳内容再次导出节点。

实现思路：归档、节点管理、工程管理各守职责；工程公共结构与能力自有内容分开；逻辑内容摘要与压缩/加密字节分开。利用 M1 真实模型扩展，不建设另一套运行模型。

步内验证：
1. 7z `.crnd`/`.crnp` 打包读取、损坏识别、失败写入保护原文件和非 ASCII 路径。
2. 外部引用与完整收纳两种路径，同内容去重、实例独立、多版本并存、内容冲突、递归引用有限收集。
3. 缺依赖与未知内容保真保存；完整导出缺项明确阻断或明确选择保留外部引用，不伪报完整。
4. 从工程实际保存副本批量导出，检查分类、目录保留和覆盖处理；外部源不可用仍可导出已完整收纳内容。
5. 文件占用只读、另存、设计恢复、源更新及实例覆盖冲突；锁不充当备份。
6. 上锁、解锁默认去锁覆盖、另存保留原件、错误密码/取消/写入失败保护原件，无密码持久化和泄漏。
7. 源码、说明、图片与重建材料完整携带，离开旧归档和原机路径后能核对恢复。

完成条件：在清楚隔离的目标目录/环境实际恢复、运行 M1 工程并重新导出；验证引用、内容身份和加密规则；证据说明所用依赖从何获得，不将复制开发环境伪称完整交付。

## 7. M3：首个节点装配编辑器

**结果**：用户在官方 `.crnp` 装配的 CoRig 中，从节点库放节点、连线、配置参数、保存重开并运行 M1 工程。

实现思路：工程管理、节点库、编辑、容器、运行控制和软件配套各由节点/组合提供，普通入口仅负责必要装载。GUI 与 CLI 调用同一公开能力，节点属性视图由所属节点提供。

步内验证：
1. 在投入大量 GUI 代码前，用实际节点视图确认承载与焦点机制；ADS 等仍按真实支持与许可验证，不能直接宣布锁定。
2. 官方装配工程启动编辑器；应用生命周期、信息、对话框、配置存储等配套能力在本步按所需范围真实接入。
3. 库浏览不启动节点；放置、连线、参数编辑、删除影响与撤销经过修订和原子提交。
4. 保存重开保留真实模型和布局；启动 M1 工程得到相同结果；节点实例与视图引用一致。
5. 同时打开两个业务工程，运行/保存/撤销目标正确；停止业务工程不停止编辑器。
6. 可用兼容替代实现经公开接口替换一项能力，不修改入口或其他节点的内部代码。

完成条件：真实 GUI 操作及公开程序调用均有证据；无固定主程序包办业务、无不可交付的验证专用结构。可用编辑器不等于全部界面能力已完成，M4 继续补全。

## 8. M4：完整编辑、多页面与 AI

**结果**：复杂工程可以封装复用、跨窗口整理，并通过 GUI 和一个 AI 共用编辑能力。

实施范围：组合与形状、接口内外角色和绑定、原地封装/展开/拆开、节点自定义属性、复杂工具预览、多选与外部编辑、多页导航、嵌套容器、跨工程工作区、快捷键上下文、结构化 AI 接入。

步内验证：
- 应用/完成/取消、局部与工程撤销、预览期间保存、切工程返回预览、关闭处理，无隐式应用或草稿恢复。
- 运算和接口变更的连线保留及冲突预览、源工程更新、组合递归与独立实例；成员越界只报警告。
- 跨窗口拖出拖回、浮动分组、标签重组、多工程混排、工作区保存恢复，节点和会话身份不变。
- 节点自绘及混合承载的焦点、输入、资源恢复与实际负载；视图关闭不停止业务，切页不丢配置。
- AI 与用户共用页面选择工具；忙时拒绝修改而非积压，查询/取消可用；离线仅丢未应用内容。

完成条件：以 CoRig 自身及多工程场景验证完整交互；明确承载支持矩阵和实际性能，不以空窗口或拖动截图代替。

## 9. M5：真实联调、计算与任务

**结果**：用户能搭建串口/网络/SSH 收发、协议解析、控制和计算工程，并查询、调试和结束实际任务。

实施范围：FEATURE_MAP 中通信、协议、控件、数学逻辑、信号源/处理、条件门控、表达式、Python、终端及相应官方运行调试能力。节点按完整用途归并，功能不可因合并而消失。

步内验证：
- 串口与 TCP/UDP 收发、连接/断开/重连、服务端多客户端、来源隔离、定向与广播；SSH 认证、主机指纹、PTY 与终端。
- 文本/HEX、编码转义、快捷命令、文件发送取消与记录；不同来源解析缓存、错误帧及恢复。
- 同源分支、独立来源同步、缺失/过期、本地值、多来源、反馈、运算切换与状态处理，逐项核对结果。
- 运行/暂停/结束/重置、参数生效、运行期结构修改、节点/组合单步与异步终态；按能力提供而非强制遍历全部节点。
- 外部程序参数、输出、超时、取消、资源回收和关闭任务；必要提权由本次任务辅助进程处理。

完成条件：代表性真实联调工程可保存重开，公开接口和 GUI 行为一致。没有实机或外部服务的项目明确未验，不以回环替代物理验证；影响本步验收的缺项交用户处理。

## 10. M6：观测、录制与回放

**结果**：可观察多通道数据、XY 和三维位姿，完整记录并按时间语义回放受支持类型。

实施范围：完整曲线、XY、姿态/位姿、rosbag2＋MCAP 录制和回放，以及关联时间、分段、动态通道和说明。

步内验证：
- 历史、命名/显隐/颜色、平移缩放跟随冻结、游标统计、FFT、CSV 和图片导出；共享数据而视图配置独立。
- 模型、旋转顺序、单位、轴映射、参考变换、位置/姿态和失效提示；多视图和独立计算进程真实承载。
- Windows 下 rosbag2＋MCAP 构建与多类型编码，文件记录实际定义、来源、时间和顺序；脱离生产节点离线读取。
- 多流录制、启停通道、暂停分段、回放统一时间轴、变速、跳转、断档与时间跳变；修改文件引起端口冲突时明确处理。
- 实际曲线/3D/录制负载下跨窗口、页面隐藏与工作区恢复，记录输入规模和耗时/资源，不预先编造性能指标。

完成条件：记录可独立读取并核对内容，回放不误执行原设备动作；性能基于固定工作负载可重跑，未知上限与未验场景如实列出。

## 11. M7：独立发布与源码重建

**结果**：普通应用与 CoRig 自身由同一公开发布能力生成独立 EXE；可从携带源码工程的产物导出并重建。

实施范围：依赖收集提供者、发布配置和快照、单文件运行、可选 API、可选完整源码工程、外部导出和失败清理。

步内验证：
- 在没有开发工具链和旧 CoRig 的 Windows 环境运行普通无界面应用和 CoRig 编辑器；核对必要依赖、实际功能及所选落盘位置。
- API 开关、随机令牌和实际目录；发布配置不存密码或令牌；关闭 API 不影响内部公开接口。
- 发布快照与原工程独立，运行参数另存；自运行编辑器不获得隐含自编辑特权。
- 不启动目标程序即可提取其携带 `.crnp`；未携带源码与缺运行依赖分别报告。
- 官方源码从产物导出到独立目录，按版本、生成步骤和材料重建，并执行关键行为验证。
- 缺依赖、收集或写入失败不生成“成功”产物，不清理用户无关文件。

完成条件：真实离线运行与源码重建均有证据，依赖和许可材料完整，不能只展示 EXE 存在或包内 source 目录。

## 12. M8：可选安装、更新与卸载

**结果**：官方安装器、更新和卸载能力作为普通工程/节点交付，可以独立完成各自任务。

实施范围：选定位置与范围、系统登记、必要提权、安装清单、更新切换恢复、卸载数据选择。工具链按实际需要核查，不默认恢复整套 IFW。

步内验证：
- 当前用户和所有用户安装、不可写路径、取消 UAC、辅助进程回收；安装器完成后删除也能更新卸载。
- 完整清单更新、暂存校验、运行任务与未保存内容处理、启动失败恢复、离线更新；不覆盖用户数据。
- 主程序损坏时卸载入口可用；默认保留数据，完全删除明确展示并确认范围，目录外数据独立选择，不沿链接扩大。

完成条件：在隔离测试目录/环境实际安装、更新失败恢复、卸载并核对残留和登记。不得以测试名义替换用户正在使用的安装版。
