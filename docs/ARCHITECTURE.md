# CoRig 0.5.0 架构

更新：2026-11-11。本文描述目标设计，不表示相应代码已经存在或通过验证。

## 1. 依据、边界与阅读顺序

CoRig 用节点工程构造可视化联调工具，也用同一种工程构造自身。当前目标为 Windows x64；Linux、macOS 为后续目标，平台边界应保持清楚。

设计依据是 [决策讨论记录](design-discussion/DECISIONS_20261110.md)。其中第 19 节 D-127～D-153 及明确替代关系优先于早期表述；具体节点默认行为不得扩大成所有节点的准入条件。该记录中的旧授权、旧目录、旧阶段和“尚未写施工计划”等表述属于当时状态；2026-11-11 后续用户已授权初始化当前文档和 Git 分支安排，不代表新源码已经实施。

执行方式、阶段与工作规则见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)，实际进度见 [PROGRESS.md](PROGRESS.md)，功能追踪见 [FEATURE_MAP.md](FEATURE_MAP.md)。本文不维护完成勾选或测试成绩。

## 2. 最小共同约定与程序身份

| 对象 | 职责 |
|---|---|
| `.crnd` 原子节点 | 携带实际程序、公开接口、声明、资源及交付材料；按完整用途划分，不要求只实现一个函数 |
| `.crnp` 节点工程 | 保存节点组合、引用、连接、参数、视图和容器；可以直接编辑运行，也可以作为其他工程的节点 |
| 节点实例 | 一个具体使用位置；默认拥有独立配置和运行状态 |
| 执行单元 | 实际执行承载的组织单位，与 CR 节点、线程、进程不一一对应 |
| 工程会话 | 打开后的设计及运行上下文；会话存在与正在运行分开 |
| 普通内部库 | 复用算法、装载、序列化等内部实现，不拥有永久全局产品状态或业务决策 |

取消 `.crpl`、独立插件执行体系和 `.crpj` 文件身份，不建立新旧格式长期兼容路径。统一节点库管理 `.crnd` 与 `.crnp`。

共同约定仅覆盖互操作所需的文件与内容身份、实例与引用、公开接口、依赖和接入条件。节点只声明实际能力，不强制所有节点提供暂停、重置、单步、批次或视图；不要求空函数，不设万能节点基类和永久产品业务中心。

SDK 按需提供生成和复用实现。简单计算节点只负责其计算；资源管理和持续任务按实际需要实现。不同程序可采用自己的内部结构，只需履行实际使用的公开契约。

## 3. 官方能力与职责边界

以下是职责归属，不预先要求每一行等于一个原子节点或一个进程。原子与组合按完整使用目的划分。

| 能力 | 拥有的内容 | 不应承担的内容 |
|---|---|---|
| 入口与运行装配 | 初始装载、实际依赖解析、提供者绑定、启动协调与失败收尾 | 全部业务状态、固定软件全局命令表 |
| 契约管理 | 定义发现、版本和格式检查、声明查询 | 手工集中定义所有业务接口、转发每条消息 |
| 节点文件管理 | 包读取、位置、版本库存、安装移除和导出 | 根据扫描顺序决定实际运行版本 |
| 节点库视图 | 分类、搜索、详情和发起操作 | 独立库存、浏览时启动节点或设备 |
| 工程管理 | 会话、设计文档、修订、原子提交和保存协调 | 解释每种业务节点的私有数据 |
| 节点与布局编辑 | 生成本职责的修改、影响和预览 | 直接写其他能力的内部状态 |
| 撤销 | 会话内设计历史，通过共同提交机制操作 | 撤销已发生的设备动作、消息或文件写入 |
| 执行支持与运行控制 | 实际通信执行、工程选定的控制语义与诊断 | 强制第三方节点遵循完整统一状态机 |
| 视图与容器 | 显式承载、布局、页面和用户工作区 | 根据视图缺失推断删除业务节点 |
| 外部程序执行 | 程序、参数、环境、输入输出、取消、退出与进程回收 | 理解编译、安装等每类业务流程 |
| 归档 | 7z 读取、打包、解包、加解密和校验 | 密码记忆、持久凭据管理 |
| 发布 | 从选定工程及依赖生成 EXE、校验产物和失败清理 | 为不同语言或安装用途堆积特权分支 |
| 文档与本地化 | 按声明生成说明、保留用户内容、渲染和译文解析 | 重复维护接口字段和所有节点文案 |
| 软件配套 | 应用生命周期、信息、系统交互、对话框和配置存储 | 将用户全部运行状态自动持久化 |

官方 CoRig 是预装配、绑定好界面的普通 `.crnp`。它自身的会话与所编辑的业务工程隔离：停止业务工程不停止编辑器、节点库等应用能力。官方节点没有绕过公开接口的特权，第三方应能在不修改装配入口或其他节点内部实现的情况下接入或替换兼容实现。

## 4. 文件、内容与保存

`.crnd` 和 `.crnp` 使用 7z 容器，可选整体加密；开发时可以使用与正式模型一致的展开目录。正式包布局、清单字段和格式版本需在相应实施步骤定义并真实验证，不能另造仅供演示的隐藏格式。

格式版本、节点版本和逻辑内容摘要分别管理。重新压缩、上锁和解锁不改变逻辑内容身份，实际程序、接口、配置、结构或资源变化应反映为内容变化。

使用节点时允许外部引用或完整收纳。完整收纳保存实际程序、定义、资源、结构和必需依赖，同一确定内容存一份，实例状态仍独立；递归保留引用关系，避免无限复制。完整收纳与拆开组合是不同操作。缺少必需依赖时不得声称完整交付，但普通保存仍应保真保留缺依赖工程。

同标识同版本但不同内容必须报告冲突。同一工程允许多个版本并存，每个实例绑定确定内容，安装新版不自动替换运行实例。运行冲突只能用实际支持的隔离方式处理。

编辑先发生在会话中，保存写回实际文件。同一文件只允许一个可写打开者，其他打开者只读。文件占用、未保存设计恢复与备份分开。普通保存保留设计，包括已应用但运行中尚未生效的修改；不保存设备句柄、任意内存或运行队列。

实例配置不静默写回外部源文件。源保存后提示引用者更新，由用户明确切换并检查冲突。导出使用明确选择对象实际保存的内容，不回退到节点库原件。未知扩展内容、资源和引用应保真保留，不能因缺解释能力而保存成默认值。

解锁默认在校验完成后覆盖为未加密文件，可另存并保留原件；密码错误、取消或失败保护原文件。未解锁时仅显示文件名和锁定状态。密码只用于本次操作，不记忆、不写工程、发布配置或日志；解锁后的内容不自动重新上锁。

全部应用可控默认位置允许选择，并显示实际位置与来源。位置不可用时明确报告，不静默换盘或路径；修改默认位置不自动迁移已有文件。程序与用户内容按归属区分。

## 5. 接口、通信、执行与启动

公开接口语言中立，官方实现以 C++ 为主。消息、服务、动作的字段和类型来自 `.msg`、`.srv`、`.action`；JSON 清单只保存引用与补充元数据，不重复定义接口字段。格式标识和版本需显式匹配，后缀不等于自动依赖 ROS。

新增类型在开发构建和打包阶段生成相应支持并交付；日常使用已有类型不要求接收方安装编译器。消息负责数据或事件，服务负责请求响应，动作负责反馈、结果和取消。队列、顺序、丢失与满载保证应可检查，不能静默降级。

官方执行方案复用 ROS 2 通信和执行调度，不再实现平行通用调度器。ROS 依赖属于实际执行实现，不成为所有节点的固有身份。多个兼容 CR 节点默认共享执行单元与执行器；独立进程、运行环境或已有 ROS 程序有实际需要时再拆分。嵌套 `.crnp` 不自动新建进程或下级调度。

工程引用、启动依赖、运行连接与容器层级各有含义。启动前检查实际依赖和接入条件，必需启动依赖成环时报完整链路。工程递归允许按明确条件展开并受额度限制；计算反馈由相应能力用显式延迟或状态处理，不将所有“环”统一禁止。

入口由相应节点交付预构建程序，携带最小必要读取和装载代码作为内部库，避免必须先运行尚未装入的契约、ROS 或归档服务才能装入自己。启动失败时收尾本次取得的资源，不直接停止其他会话仍在使用的共享实例。

API、CLI、HTTP、GUI 与 AI 定位到“工程会话 → 节点实例 → 公开接口”。目录由实际装配声明生成；接入转换与路由，业务能力校验并执行。任务 ID 或受理响应不表示完成，必须读取终态和真实结果。

本机 API 可选，发布默认开启，使用每次启动重新产生的令牌及本机连接信息；令牌不写入工程、发布配置和日志。GUI 内部不必绕行 HTTP。不建立通用角色或权限授予体系。

## 6. 运行、参数、时间与故障

以下为相应官方能力的设计输入，不是所有第三方节点的统一义务：

- 运行、暂停/继续、结束运行、重置与关闭会话分开。暂停请求与实际到达边界分开；结束释放运行资源，仍保留可检查保存的工程会话。
- 重置恢复相关计算状态、队列与计时，保留工程配置、采集结果、录制和导入数据，不自动启动或设备回零。运行中先结束再重置。
- 参数声明生效时机，查询区分配置值与生效值。运行与暂停均可编辑结构，按影响准备和切换，未生效部分明确显示；失败不虚报回滚。
- 节点及组合/分组单步以真实业务完成为边界，异步受理不算完成，无就绪输入不生成虚假数据。取消调试模式总开关，观测快照和追踪按需开启。
- 并发、重试、崩溃与恢复由所属节点及工程流程决定。官方可提供默认处理，不强制全体暂停，不自动重放副作用调用。
- 相应普通实时计算默认实例内串行、实例间可并行，待处理批次可整体保留最新并统计跳过；事件、动作和完整记录不套用这一丢弃策略。
- 同源分支保持批次，独立来源可显式选严格时间匹配、近似同步或主输入加最近有效值。过期和未到达不补零；优先按需复用 message_filters。
- 业务时间与真实耗时分开，复用 ROS Time/System Time/Steady Time。时间跳变通知相关处理段，有状态算法按自身规则处理，不能将全部节点一律重置。

进程执行默认后台非交互、直接传程序与参数；Shell 与交互终端是显式能力。取消需等待退出和收尾，不能暗示已执行效果被撤销。同一提权任务可复用 UAC 辅助进程，完成后退出；主编辑器不整体提权。关闭工程不得先销毁仍被任务使用的状态。

## 7. 编辑、封装与 AI

工程管理拥有设计修订和原子提交；各编辑能力生成本职责修改及影响。跨内容修改整体提交和撤销，不把采样或设备操作塞进设计历史。优先直接复用 Qt State Machine 与 Qt Undo Framework，合法性、业务预览和失败处理仍由所属编辑能力实现。

组合、展开和拆开复用 `.crnp` 模型。外框是组合节点展开的外壳，同一接口对外输入在内部作为来源、对外输出在内部作为出口，不增设必需转发节点或另一套边界身份。成员关系独立保存，越界只给布局警告，不修改成员或执行归属。轮廓支持曲线、圆角矩形、圆、方和胶囊等形状。

复杂工具使用虚影和预览：应用提交后留在工具，完成提交并退出，取消丢弃上次应用以来未提交内容；切换工具按完成/取消处理，不增加常规确认弹窗。预览内撤销不越过上次应用，正式提交进入工程历史。未应用预览不保存、不恢复；预览期间保存只保存已应用的设计。

节点库、工程结构/图层和当前工具默认共享左侧停靠区页签，也可拆分。切换工程保留各工程工具与预览，返回恢复。节点属性由节点自己完整提供，属性栏只是容器，不恢复官方通用自动表单；普通字段失焦或 Enter 提交，多选兼容字段可批改，多行内容交给适合格式的外部编辑器。

输出可以直接连接多个输入，输入接受多来源与本地常量由声明决定；有线但暂无数据不回退本地常量。改变运算、端口或录制通道时保留语义兼容连接，其余影响明确列出并整体提交。

一个 AI 与用户共享页面、选择、工具和预览。修改逐项处理，拖动或提交繁忙时返回实际状态，不排队积压旧修改；查询、查看与取消可用。AI 通过结构化目标使用与 GUI 相同的校验及提交能力，不模拟鼠标。离线丢弃 AI 未应用内容，保留已应用修改。不建设多 AI 独立视角、跟随和交接系统。

## 8. 视图、页面与容器

图和视图引用同一业务节点，显示配置独立；删除或关闭视图不删除节点、不停止业务。批量生成视图是明确操作，不依据缺失视图自动同步删除节点。

支持同工程多页面、导航、自由布局、锚定、分栏、网格、标签、停靠与嵌套，以及跨窗口拖出拖回、浮动分组、标签重组。跨工程视图可混排，节点、会话和快捷键目标保持正确。复制页面默认复制布局及视图引用，独立复制业务节点需明确选择。

工程默认布局保存到 `.crnp`；运行时用户工作区另存，不暗改官方工程。切页保留选择、相机和滚动等视图状态，减少无用重绘但不停止采集计算。

视图和容器声明承载要求与支持范围。可按场景选 QML、Widgets 或其他技术，不承诺任意图形对象自动兼容。ADS 只是优先验证候选；跨窗口、多工程、实时曲线、3D、工作区恢复和离线发布必须实测后再确定实现。计算与视图按实际支持情况可分进程，仍对应同一逻辑实例，不要求用户手工放代理节点。

## 9. 官方业务能力

通信按完整连接组织：串口、TCP/UDP、SSH 等节点负责连接、双向收发、状态与回收，编解码独立。TCP 服务端管理多客户端并提供来源标识、定向发送和广播；解析缓存按来源隔离。常用组合可作为 `.crnp` 直接交付。

数学与逻辑按数学运算、逻辑运算、条件门控、信号生成、信号处理、触发器和表达式等完整用途归类；常量、时间、Python 函数用途明确。运算切换保留实例，动态接口影响按编辑规则处理。

曲线包括历史、命名/显隐/颜色、缩放平移跟随冻结、游标、区间统计、FFT 和数据图片导出。姿态与三维位姿合并，支持位置/姿态、模型、单位、轴映射、旋转约定、参考变换及失效提示；不隐式提供融合或运动求解。

录制和回放是两个完整节点，选用 rosbag2＋MCAP 作为内部依赖。覆盖受支持消息类型及定义、版本、编码、来源、时间、顺序和分段；不把服务或设备动作自动变成可重放行为。多流同时间轴，变速保留原始时间，暂停分段与断档如实表达。Windows 集成、编码及发布仍待验证。

完整能力与旧功能去向以功能追踪表逐项验收，不能以合并节点为由削减行为。

## 10. 发布、源码、安装与文档

统一发布仅负责将节点工程及必要依赖生成 EXE；它是普通软件、CoRig、安装器还是更新辅助，由工程内容决定。单 EXE 指交付单文件，允许按选定位置释放必要内容。依赖收集由实际能力提供，接收方不需先装 CoRig 或开发环境。

发布固定选定并保存的设计快照，运行持久修改另存；原 `.crnp` 改动不改变既有 EXE。可携带完整工程与实际提供的源码、资源和重建材料。外部导出能力可不启动目标 EXE 就提取 `.crnp`，包括无图形程序。官方源码不加密，需独立目录导出、重建并验证，不只检查压缩包存在。

应用启动、就绪、退出请求、配置保存及自动运行由相应节点和工程表达；不把托盘或特定退出入口作为所有应用限制。

安装、更新、卸载为可选独立能力，同样由节点工程生成。安装器完成后可以删除，更新和卸载不依赖原安装器。撤回默认整套采用 Qt Installer Framework 的路线。官方更新按完整发布清单暂存校验、切换及失败恢复，保留用户内容；卸载默认保留用户数据，完全删除必须展示选定范围并明确确认，不沿链接扩大到外部目标。

说明生成、Markdown 渲染与本地化按职责分开。接口定义、JSON 元数据和 Markdown 用户正文各有唯一来源。生成区和用户区使用稳定起止标记；重生成保留用户区和资源，失去关联内容可重新归属，边界损坏时保护原文件。图片按包内资源携带。官方声明和说明提供中英文；第三方缺译文可回退默认语言。

## 11. 实现前必须查证的事项
